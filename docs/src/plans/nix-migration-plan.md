# asetland Nix Migration Plan

Status: Phase 1 done; remaining phases deferred (compose stays manual).

## Objective

Move reproducible build steps, tool fetches, images, config files, and runtime
services in `mc-aset-loveland` to declarative Nix (`flake.nix` + `nix/`) when
it pays off, without taking manual `docker compose up/down` away. Impure
Modrinth/loader resolution stays cleanly bounded.

## Current state

- `flake.nix` exposes `formatter` + `checks.treefmt` (shared
  `inputs.nixos.flakeModules.treefmt`: shellcheck, shfmt, statix, deadnix,
  prettier, eslint), `devShells.default` (treefmt tools + `nodejs`, `pnpm`), and
  `nixosModules.asetland`.
- `nix/module.nix` (`services.asetland`) wraps the compose project in systemd
  units but is inert by default: `autoStart = false` (no `wantedBy`),
  `backupSchedule = null` (no timer), and `asetland-backup` never `wants` the
  stack. It is the hook for any later Nix takeover; compose stays the manual
  source of truth until then.
- Still outside Nix: `Dockerfile` + `scripts/install-pack.sh` (online JRE /
  Forge / `mrpack-install` + mod downloads), `backup.dockerfile`
  (`apk add`), itzg `bias` (root privilege drop, runtime mod pulls over
  `mc-egress`), `playit-agent`, plain `server.properties` / `c2me.toml` /
  `eula.txt`, and secrets in host `.env`.

## Decisions

1. **Compose stays manual.** No phase may auto-start, stop, or recreate the
   stack; new Nix behavior is opt-in through `services.asetland` options.
2. **Split impure resolution from pure builds.** `pnpm run update`
   (`scripts/update.ts`, `scripts/loaders.ts`) stays impure on the developer
   machine and emits the `.mrpack`; Nix would consume the locked output purely.
3. **Prefer pinned `nixpkgs` packages**: `mrpack-install`, `mc-monitor`,
   `javaPackages.compiler.temurin-bin.jre-*`, `zstd`, `restic`, `pv`,
   `coreutils`, `gnutar`.
4. **Native systemd only behind an option**, modeled on nixpkgs
   `minecraft-server.nix` (`ListenFIFO` console, `CapabilityBoundingSet = [ "" ]`,
   `DynamicUser`), never replacing compose implicitly.

## Phases

### Phase 1 — devShell + checks (done)

`devShells.default` added; lint checks already run via `checks.treefmt`.

### Deferred

- **Nix-built pack / OCI images**: read `modrinth.index.json`, `fetchurl` each
  server-side mod (sha512) into a `linkFarm`, pick JRE from `temurin-bin`, and
  emit `dockerTools.buildLayeredImage` (`User = "65532:65532"`) to replace
  `Dockerfile` + `install-pack.sh`. Fabric (`server`) is pure; NeoForge (`bias`)
  / Forge (`serverpack`) installers need `nix-minecraft` or a Maven lock / FOD.
- **Backup image**: `dockerTools` image (or `writeShellApplication`) replacing
  `backup.dockerfile`; a native host backup is blocked on reading compose
  volumes from outside the worker.
- **Native systemd instances** (`services.asetland.instances.<name>`): FIFO
  console replaces `mc-send-to-console` in `backup.sh`, `127.0.0.1:25564` bind,
  full sandboxing, generated `server.properties` (`formats.javaProperties`) and
  `c2me.toml` (`formats.toml`).
- **`playit-agent`**: not in nixpkgs; package (`rustPlatform.buildRustPackage`)
  or keep the `latest` container.
- **Secrets**: `sops-nix` for `SECRET_KEY` / `RESTIC_PASSWORD` via the existing
  `envFile` option instead of host `.env`.

## Rollout order

1. Pick up a deferred item only on explicit request; land it as an opt-in
   `services.asetland` option or flake output.
2. Fabric `server` profile first (fully pure), verified against a world copy.
3. NeoForge `bias` only after loader purity is solved.
4. Retire `Dockerfile` / `backup.dockerfile` / `install-pack.sh` only once their
   Nix replacements are soak-tested; `compose.yaml` stays as long as manual
   up/down is wanted.

## Open questions

1. **Host target:** native NixOS units via `services.asetland` or Nix-built OCI
   images for the compose host?
2. **NeoForge 26.3 loader purity:** `nix-minecraft` input, or a loader/Maven
   lockfile generated by `scripts/update.ts`?
3. **Whitelist & ops:** declarative in Nix, or mutable state via the console?
4. **`playit-agent`:** build from source, or keep the `latest` container?
