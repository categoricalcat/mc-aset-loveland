# MC 26.3 + all-mods upgrade

Status: in-progress (Phase A staged)

## Objective

Upgrade both servers to Minecraft 26.3 (latest release) and every mod to its latest 26.3-compatible build.

## Current state

- `bias` (live, playit tunnel): NeoForge 1.21.11 / neoforge 21.11.38-beta, ~130 mods from `bias-processed.mrpack`, runs on `itzg/minecraft-server:latest`, world in volume `mc-bias`
- `server` (profile): Fabric 1.21.5 / loader 0.16.14, ~110 mods from `the-modpack 1.1.mrpack`, custom image via [Dockerfile](Dockerfile), world in volume `mc-data`
- Latest MC release: 26.3 (Mojang year-based versioning); NeoForge 26.3.0.102 available; spot-check shows sodium/jei/terralith already have 26.3 builds
- Known-stale mods already in bias: `stackedblocks` (1.21.5 build), `toomanypaintings` (1.21.3 build)
- Legacy `serverpack` (1.16.5): out of scope, untouched

## Would it break — known risks

- World upgrade is one-way (1.21.x -> 26.3); no downgrade path. Mitigate with `backup` profile before touching anything.
- Some of ~240 total mods will lack 26.3 builds -> must drop, substitute, or pin. Phase 0 produces the exact list.
- All players must update clients to 26.3 + matching mod set.
- `mc-bias` volume holds both mods and world: do NOT wipe; rely on itzg mrpack re-apply (verify it reconciles changed mrpack).

## Decisions

- Scope: both servers (user: "everything")
- Target: latest MC 26.3 + latest mods (user-selected)
- Mod resolution: **Prism Launcher-driven**. User maintains packs in Prism; Prism's updater filters Modrinth by MC+loader and resolves deps. No scripted mrpack regeneration — Prism export is the source of truth, repo processor only fixes env flags.
- Scripted work limited to: Phase 0 availability probe (read-only, `/tmp/ai/` scratch) and compose/Dockerfile version bumps.

## Phases

### Phase A — build + backup hardening (lands before any upgrade work)

- `.dockerignore`: excludes `.git`, `.backups`, `node_modules`, `home/`, `docs/`, `*.log`, and `bias*.mrpack`; keeps `ServerPack.zip` and `the-modpack*.mrpack` for `COPY ["${PACK}", "/tmp/pack"]`.
- [Dockerfile](Dockerfile): unified pack image (`debian:stable-slim` builder running [install-pack.sh](scripts/install-pack.sh) -> `gcr.io/distroless/cc-debian13:debug` runner with Adoptium JRE in `/opt/java` and pack in `/opt/pack`); [start-server.sh](scripts/start-server.sh) stages `/opt/pack` into `/data` on start.
- [backup.dockerfile](backup.dockerfile): `ubuntu:22.04` -> `alpine:3` (`zstd`, `restic`, `pv`, `coreutils`, `tar`), shared across `backup`, `restore`, and `restic`.
- [backup.sh](scripts/backup.sh) + [compose.yaml](compose.yaml): excludes reproducible dirs (`mods`, `libraries`, caches, logs, `versions`, `*.jar`), parametrizes `BACKUP_VOLUME` (default `mc-bias`), uses per-volume `latest-${VOLUME}.tar.zst` copies, and supports optional `RESTIC=1` incremental snapshots.

### Phase 0 — availability report (gate, scripted)

- Extract project IDs from both mrpack manifests (`modrinth.index.json` download URLs contain project/version IDs)
- Query Modrinth `/v2/project/{id}/version?game_versions=["26.3"]&loaders=[...]` per project
- Output: per-pack list of mods WITH 26.3 build and WITHOUT (drop/wait/substitute) — so user knows what Prism will refuse to update before starting
- User reviews missing list before proceeding

### Phase 1 — Prism upgrade (user-driven, per pack: bias then Fabric)

- Duplicate the instance in Prism (never upgrade the working one)
- Set MC 26.3 + loader: NeoForge 26.3.0.102 (bias) / latest Fabric loader
- Select all mods -> check for updates; Prism pulls 26.3 builds where they exist
- Decide drop/substitute for mods flagged missing in Phase 0
- Boot test the client in Prism — catches missing deps/crashes before server sees it
- Export mrpack

### Phase 2 — backup (uses Phase A wiring)

- `docker compose --profile backup run --rm backup write` (backs up `mc-bias`)
- `BACKUP_VOLUME=mc-data docker compose --profile backup run --rm backup write` (Fabric world, now wired)
- Verify `.backups/` artifacts exist, non-empty, and contain `world/` but no `mods/`

### Phase 3 — bias (NeoForge) deploy

- Replace `bias.mrpack` with Prism export; `pnpm run process` -> `bias-processed.mrpack` (env flags preserved for itzg)
- No compose version bump: bias is `TYPE=MODRINTH`, versions come from the mrpack
- `docker compose up -d --force-recreate bias`; verify mrpack re-apply in logs, server healthy, world loads

### Phase 4 — Fabric server deploy

- Replace `the-modpack.mrpack` with Prism export; `pnpm run process` if processed variant is used
- Update `MODPACK_ARCHIVE` arg in compose if filename changes
- Java is resolved from Mojang metadata at build ([install-pack.sh](scripts/install-pack.sh)); no manual bump
- `docker compose build server && docker compose up -d --force-recreate server`; verify boot + world load

### Phase 5 — verification + docs

- Both servers: `docker compose logs` clean (no missing-mod/dependency errors), `mc-monitor` healthcheck green, test client join
- Update [README.md](README.md) version references (1.21.5 -> 26.3)
- Delete this plan file on completion

## Rollout order

1. Phase A build + backup hardening
2. Phase 0 availability report (agent, read-only)
3. Phase 1 Prism upgrade per pack (user) -> mrpack exports
4. Phase 2 backups of both volumes (verified)
5. Phase 3 bias deploy (live server; players impacted first)
6. Phase 4 Fabric deploy
7. Phase 5 verify + docs + retire plan
